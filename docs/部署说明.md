# 部署说明

## 1. 创建 Supabase 项目

在 Supabase 新建项目后，安装 CLI，并确认版本：

```bash
supabase --version
supabase login
supabase link --project-ref 你的项目编号
supabase db push
```

迁移会创建 `public.books` 表、索引和逐操作 RLS 策略。表只向 `authenticated` 角色授予增删改查权限，`anon` 不能访问书架数据。

## 2. 部署 ISBN 查询函数

```bash
supabase functions deploy book-lookup
```

`supabase/config.toml` 为函数保留平台级 key 校验。免注册模式会把 publishable key 放在 `apikey` 请求头中；登录用户还会发送自己的访问令牌。

以下第三方变量均为可选项，只能配置到 Edge Function：

```bash
supabase secrets set GOOGLE_BOOKS_API_KEY=你的值
supabase secrets set JISU_API_KEY=你的值
supabase secrets set DOUBAN_API_KEY=你的值
supabase secrets set DOUBAN_PROXY_URL=你的值
supabase secrets set DOMESTIC_ISBN_PROXY_URL=你的值
```

## 3. 配置邮箱验证码

在 Supabase Dashboard 的 Authentication 中启用邮箱登录，把正式站点地址加入 Site URL 和 Redirect URLs。

将 Magic Link 邮件模板改为显示验证码：

```html
<h2>扫书架登录验证码</h2>
<p>验证码：<strong>{{ .Token }}</strong></p>
<p>如果不是你本人操作，可以忽略这封邮件。</p>
```

## 4. 配置前端变量

本地可复制 `.env.example` 为 `.env`。正式部署时，在托管平台设置：

```text
SUPABASE_URL=https://你的项目.supabase.co
SUPABASE_PUBLISHABLE_KEY=你的 publishable key
APP_URL=https://你的正式域名
```

如果项目仍使用 legacy anon key，也可以把它填入 `SUPABASE_PUBLISHABLE_KEY`。不要填写 secret key 或 `service_role` key。

## 5. 部署静态页面

Cloudflare Pages、Netlify 或 Vercel 均可使用：

- 构建命令：`npm run build:config`
- 输出目录：项目根目录 `/`

相机扫码要求 HTTPS。部署后应分别验证手机扫码、手动输入、本机保存、邮箱登录、跨设备同步、RLS 隔离和 CSV 导出。
