# 部署说明

## 1. 创建 Supabase 项目

在 Supabase 新建项目后，安装 CLI，并确认版本：

```bash
supabase --version
supabase login
supabase link --project-ref 你的项目编号
supabase db push
```

迁移会创建 `public.books` 表、索引和逐操作 RLS 策略。表只向 `authenticated` 角色授予增删改查权限，`anon` 不能访问书架数据。

## 2. 可选：部署 ISBN 聚合查询函数

前端默认可直接查询 NeoDB 中文书目、Google Books 和 Open Library，不部署函数也能使用。需要豆瓣代理、自有国内 ISBN 接口或集中控制数据源时，再部署聚合函数：

```bash
supabase functions deploy isbn-bookshelf-lookup
```

`supabase/config.toml` 关闭只适用于用户 JWT 的平台校验，函数内部会核对当前项目的 publishable/anon key。免注册模式把公开 key 放在 `apikey` 请求头中；登录用户在查书和书架共用一个 Supabase 项目时还会发送自己的访问令牌。函数优先查询 NeoDB 公共中文书目，再使用豆瓣、可选国内接口、Google Books 和 Open Library。

以下第三方变量均为可选项，只能配置到 Edge Function：

```bash
supabase secrets set GOOGLE_BOOKS_API_KEY=你的值
supabase secrets set JISU_API_KEY=你的值
supabase secrets set DOUBAN_API_KEY=你的值
supabase secrets set DOUBAN_PROXY_URL=你的值
supabase secrets set DOMESTIC_ISBN_PROXY_URL=你的值
```

## 3. 配置邮箱验证码

在 Supabase Dashboard 的 Authentication 中启用邮箱登录，把正式站点地址加入 Site URL 和 Redirect URLs。

将 Magic Link 邮件模板改为显示验证码：

```html
<h2>书迹登录验证码</h2>
<p>验证码：<strong>{{ .Token }}</strong></p>
<p>如果不是你本人操作，可以忽略这封邮件。</p>
```

## 4. 配置前端变量

本地可复制 `.env.example` 为 `.env`。正式部署时，在托管平台设置：

```text
SUPABASE_URL=https://你的项目.supabase.co
SUPABASE_PUBLISHABLE_KEY=你的 publishable key
LOOKUP_SUPABASE_URL=https://查书后端项目.supabase.co
LOOKUP_SUPABASE_PUBLISHABLE_KEY=查书后端项目的 publishable key
LOOKUP_FUNCTION_NAME=isbn-bookshelf-lookup
APP_URL=https://你的正式域名
```

`SUPABASE_*` 只负责邮箱登录和云端书架；`LOOKUP_SUPABASE_*` 只负责可选的 ISBN 聚合代理。因此只启用本机书架时，可以全部留空，仍能查询公开中文书目。两个云端功能也可以共用同一个 Supabase 项目。

如果项目仍使用 legacy anon key，也可以把它填入对应的 publishable key 变量。不要填写 secret key 或 `service_role` key。

## 5. 部署静态页面

Cloudflare Pages、Netlify 或 Vercel 均可使用：

- 构建命令：`npm run build:config`
- 输出目录：项目根目录 `/`

相机扫码要求 HTTPS。部署后应分别验证手机扫码、手动输入、本机保存、邮箱登录、跨设备同步、RLS 隔离和 CSV 导出。
