# 部署说明

## 1. 创建 Supabase 项目

在 Supabase 新建项目后，安装 CLI，并确认版本：

```bash
supabase --version
supabase login
supabase link --project-ref 你的项目编号
supabase db push
```

迁移会创建 `public.books` 表、索引和逐操作 RLS 策略。表只向 `authenticated` 角色授予增删改查权限，`anon` 不能访问书架数据。查询缓存和频率记录表同样启用 RLS，且不向浏览器角色授权。

## 2. 部署 ISBN 聚合查询函数

正式网站建议部署聚合函数，避免手机必须直接连接 NeoDB。函数会优先查询 NeoDB，把命中结果缓存三十天，并把未命中结果缓存六小时；同一客户端默认每分钟最多查询三十次。书目返回的可信封面会改写为同一 Edge Function 的代理地址，手机无需再直连 NeoDB 图片域名。

```bash
supabase functions deploy isbn-bookshelf-lookup
```

部署时设置允许访问的网页来源、频率和客户端哈希盐：

```bash
supabase secrets set ALLOWED_ORIGINS=https://你的正式域名,http://127.0.0.1:5174,http://localhost:5174
supabase secrets set LOOKUP_RATE_LIMIT_PER_MINUTE=30
supabase secrets set COVER_RATE_LIMIT_PER_MINUTE=120
supabase secrets set RATE_LIMIT_SALT=一段随机生成且不公开的字符串
```

`supabase/config.toml` 关闭只适用于用户 JWT 的平台校验，函数内部仍会核对当前项目的 publishable/anon key、请求来源和查询频率。免注册模式把公开 key 放在 `apikey` 请求头中；登录用户在查书和书架共用一个 Supabase 项目时还会发送自己的访问令牌。函数优先查询 NeoDB，主来源失败后再并行查询豆瓣、可选国内接口、Google Books 和 Open Library。

封面代理只按 ISBN 读取服务端缓存中的原始地址，不接受客户端传入任意图片网址；每次跳转都会重新校验允许域名，并限制图片格式、体积、超时和独立频率。允许域名与大小等配置集中在 `supabase/functions/isbn-bookshelf-lookup/config.ts`。

以下第三方变量均为可选项，只能配置到 Edge Function：

```bash
supabase secrets set GOOGLE_BOOKS_API_KEY=你的值
supabase secrets set JISU_API_KEY=你的值
supabase secrets set DOUBAN_API_KEY=你的值
supabase secrets set DOUBAN_PROXY_URL=你的值
supabase secrets set DOMESTIC_ISBN_PROXY_URL=你的值
```

## 3. 配置邮箱链接登录

在 Supabase Dashboard 的 Authentication 中启用邮箱登录，把正式站点地址加入 Site URL 和 Redirect URLs。个人使用或测试时可以保留 Supabase 默认邮件服务，但登录邮件只会发送给该 Supabase 组织的成员邮箱。

本项目使用默认 Magic Link。iPhone 上的 QQ 邮箱、网易邮箱等 App 可能在内置浏览器中打开链接，而这个浏览器与 Safari 的登录存储相互隔离。收到邮件后应按以下步骤操作：

1. 不要直接点击邮件中的登录按钮。
2. 长按按钮或链接，选择“在 Safari 中打开”；如果没有该选项，复制链接后粘贴到 Safari 地址栏。
3. 如果已经在邮件 App 内点击过，应回到书迹网页重新发送，再使用新链接。

如果以后要让组织成员以外的任意邮箱登录，再使用专门的事务邮件服务配置自定义 SMTP。个人 QQ 邮箱会同时开放多种第三方协议，本项目默认不要求开启。

## 4. 配置前端变量

本地可复制 `.env.example` 为 `.env`。正式部署时，在托管平台设置以下公开变量：

```text
SUPABASE_URL=https://你的项目.supabase.co
SUPABASE_PUBLISHABLE_KEY=你的 publishable key
LOOKUP_SUPABASE_URL=https://查书后端项目.supabase.co
LOOKUP_SUPABASE_PUBLISHABLE_KEY=查书后端项目的 publishable key
LOOKUP_FUNCTION_NAME=isbn-bookshelf-lookup
APP_URL=https://你的正式域名
```

`SUPABASE_*` 只负责邮箱登录和云端书架；`LOOKUP_SUPABASE_*` 只负责可选的 ISBN 聚合代理。因此只启用本机书架时，可以全部留空，仍能查询公开中文书目。两个云端功能也可以共用同一个 Supabase 项目。

如果项目仍使用 legacy anon key，也可以把它填入对应的 publishable key 变量。publishable key 允许出现在网页和 GitHub Actions Variables 中；不要填写 secret key、`service_role` key或数据库密码。

Supabase Free Plan 不会因超额自动扣费。免费额度持续超出后可能限制项目，因此仍应保留函数限流，并在 Dashboard 的 Usage 页面查看调用量。

## 5. 部署静态页面

Cloudflare Pages、Netlify 或 Vercel 均可使用：

- 构建命令：`npm run build:config`
- 输出目录：项目根目录 `/`

相机扫码要求 HTTPS。部署后应分别验证手机扫码、手动输入、本机保存、Safari 邮件链接登录、重新发送链接、跨设备同步、RLS 隔离和 CSV 导出。默认邮件服务额度较低，不应连续反复点击发送按钮。
